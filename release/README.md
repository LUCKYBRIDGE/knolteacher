# 놀티쳐 Release 안내문 작성 규칙

`user-facing-notes.md`는 GitHub Release 페이지와 앱의 업데이트 창에 그대로 표시되는 **사용자용 안내문**이다.

`public-release-history.json`은 이미 공개된 과거 Release의 제목과 설명을 사용자 관점으로 정리해 유지하기 위한 **공개 이력 기준 파일**이다. 과거 Release의 태그와 실행 파일은 바꾸지 않고, 공개 페이지에서 보이는 제목과 설명만 정리한다.

작성 원칙:

- 교사가 업데이트 후 실제로 느끼는 변화와 편의성을 중심으로 쓴다.
- 기능명은 사용자가 화면에서 보는 이름을 우선한다.
- 짧고 구체적으로 쓴다. 무엇이 좋아졌는지, 무엇을 새로 할 수 있는지, 어떤 문제가 줄었는지를 설명한다.
- PR 번호, 커밋, 소스 파일, 클래스명, XAML, workflow, SHA-256, 리팩터링 등 개발 과정은 사용자용 안내문에 쓰지 않는다.
- 외부 제품·서비스를 기능 또는 화면 구성의 구현 출처나 유사성 근거로 제시하지 않는다.
- 사용자용 공개 안내는 놀티쳐 자체의 기능, 사용 방법, 체감 변화만 설명하며 외부 제품과의 비교·계보 설명을 포함하지 않는다.
- 내부 구조를 바꾼 경우에도 사용자가 체감할 결과가 없다면 굳이 항목으로 적지 않는다.
- 보안·데이터 보호 변경은 기술 구현보다 사용자에게 어떤 정보가 어디에 저장되는지를 중심으로 설명한다.

형식:

1. 첫 줄은 `놀티쳐 vX.Y.Z 업데이트`로 작성한다.
2. 이후에는 사용자 관점의 짧은 구역 제목과 `- ` 불릿을 사용한다.
3. 인앱 업데이트 창은 일반 텍스트로 표시하므로 Markdown 헤딩 기호(`#`, `##`)에 의존하지 않는다.
4. 릴리스 전 `scripts/validate-user-facing-release-notes.ps1` 검증을 반드시 통과해야 한다.
5. 과거 공개 이력을 수정할 때는 `scripts/apply-user-facing-release-history.ps1` 검증을 통과해야 하며, 실행 파일이나 태그를 다시 만들지 않는다.

새 버전을 배포할 때는 `Directory.Build.props`, `release/release-version.txt`와 함께 `release/user-facing-notes.md`의 버전과 내용을 새 버전에 맞게 갱신한다.
