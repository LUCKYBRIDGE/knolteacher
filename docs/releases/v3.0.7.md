# KnolTeacher v3.0.7

v3.0.7은 새 기능 확대보다 **교실 장시간 사용 안정성, 놀보드 조작성, Local-Only 학생 데이터 원칙, 업데이트 신뢰성**을 강화하는 안정화 릴리스다.

## 배포 및 업데이트

- Windows 10/11 x64용 self-contained single-file 배포를 유지한다.
- GitHub Release에는 사용자 실행 파일 `놀티쳐.exe` **한 파일만** 배포한다.
- 앱의 `버전 확인` 기능은 GitHub 최신 Release와 현재 실행 파일 버전을 비교한다.
- updater는 정확히 `놀티쳐.exe` asset만 선택한다.
- 다운로드 크기와 GitHub Release SHA-256 digest를 검증한 뒤에만 현재 실행 파일을 교체한다.
- 버전은 루트 `Directory.Build.props`의 `KnolTeacherVersion`을 단일 원천으로 사용한다.
- CI는 데스크톱 코드가 변경되었는데 최신 공개 Release보다 버전이 증가하지 않은 경우 병합을 차단한다.
- 저장소 SDK는 `global.json`으로 .NET 8 계열에 고정한다.

## 놀보드 안정화

- 공통 `IWidgetLifecycle` 계약을 도입해 Activate / Deactivate / Dispose 경계를 명확히 했다.
- Timer, Memo, D-Day, Timetable 등 장시간 사용 시 누적될 수 있던 timer/event 구독을 정리한다.
- Weather, Meal, Picker, Dice, Wheel의 비동기 작업이 위젯 Hide/삭제 뒤 늦게 UI에 반영되지 않도록 취소 경계를 추가했다.
- 위젯을 실제 제거할 때 lifecycle Dispose가 호출된다.

## 놀보드 조작성

- 기존 우하단 단일 resize grip을 **8방향 resize**로 확장했다.
- 전자칠판/터치 환경을 고려해 resize hit target을 확대했다.
- TitleBar, 닫기 버튼, 줌 버튼의 터치 조작 영역을 확대했다.
- `WidgetRegistry`를 도입해 위젯별 기본 크기, 최소 크기, 중복 허용 여부, resize/zoom capability를 중앙 관리한다.
- 일반 위젯은 중복 생성 대신 기존 위젯을 앞으로 가져온다.

## 놀보드 레이아웃 저장/복원

- restore와 preset 구성 도중 발생하던 중간 Save를 억제하고 최종 상태만 저장한다.
- 위젯 개별 제거, 모두 닫기, 자동 정렬 후 저장 타이밍을 일관화했다.
- 사용자가 모든 위젯을 제거한 빈 custom workspace도 다음 실행 때 그대로 유지한다.
- 레이아웃 schema v2에 저장 당시 Canvas 크기를 기록한다.
- 다른 해상도/모니터에서 열 때 위치와 크기를 비례 복원한다.
- NaN/Infinity 좌표와 Canvas 경계 이탈을 방어한다.

## 학생 데이터: 번호 우선 / Local-Only

- 신규 기본 명렬은 실제 이름 없이 **1~25번 번호-only**로 생성한다.
- 학생 이름은 필수가 아니며 번호만으로 발표자 추첨 등 핵심 수업 기능을 사용할 수 있다.
- 기존 사용자의 로컬 명렬에 이름 등 정보가 있으면 자동 삭제하지 않는다.
- 개인정보 저장은 명시적인 로컬 opt-in으로 사용한다.
- 개인정보 저장을 끄면 학생 번호와 비민감 아바타만 저장한다.
- 학생 개인정보를 서버, 클라우드 동기화, 원격 텔레메트리 또는 외부 AI로 자동 전송하지 않는다.

## 로컬 저장 안전성

- `SafeLocalFileStore`를 도입했다.
- 학생 명렬 저장은 임시 파일 기록 → disk flush → atomic replace 순서로 수행한다.
- 직전 정상 파일을 로컬 `.bak`으로 유지한다.
- primary JSON이 읽히더라도 파싱/역직렬화가 실패하면 손상으로 판단하고 `.bak`을 검증해 복구한다.
- backup 복구 후 정상 backup이 손상 원본으로 덮이지 않도록 보호한다.
- 개인정보 저장 OFF 전환 시 primary뿐 아니라 이전 `.bak`에 남은 이름/성별/연락처/메모도 제거하고 번호-only backup을 다시 만든다.

## 자동 검증

CI의 완료 조건을 다음 순서로 강화했다.

1. 버전 계약 검증
2. .NET restore
3. WPF Release build
4. xUnit persistence/service contract tests
5. `publish.bat` 실행
6. `dist-net`에 `놀티쳐.exe` 한 파일만 존재하는지 검증

`SafeLocalFileStore`의 첫 저장, backup 생성, backup 복구, known-good backup 보존, 개인정보 scrub을 실제 임시 파일 시스템에서 자동 테스트한다.
